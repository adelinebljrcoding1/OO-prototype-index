Bánh mì 700
--fw-bold · 700 · reserved
Not used by any role. All emphasis (overlines, badges, prices, links, bold meta) is 600, so no small text outweighs a heading. Keep the token for a future need; don't use it on screens.
Per-role tokens: each role reads its weight from its own token (--fw-display, --fw-title-1 … --fw-callout, --fw-overline, all 600 today), so a role can change weight in one place without touching any screen.
Retired: 500 (used on .mealdetail-desc, .signin-benefit-row): use 400. 900 (.visa-icon): this is a logo mark, so swap it for the real card-brand SVG. Also retired: the stray 'Inter' font-family on .mealdetail-desc. Inter is never loaded, so that element falls back to the system font anyway.

Rules for new screens

6 rules
DoChoose by role, not by sizeAsk "is this a screen title, a sheet title, or a section heading?" and use that style. If none fits, reuse the closest one. Don't add a size.
DoOne title per screenEach screen gets exactly one t-title-1. Bottom sheets and modals use t-title-2. Headings inside a screen use t-title-3.
DoLet the tokens handle desktopNever write html.is-desktop .x{font-size:…}. Title tiers already grow on html.is-desktop. If an element needs a different role on desktop, swap the class.
DoInputs are 16pxEvery <input>, <select> and <textarea> uses t-input. Below 16px, iOS Safari zooms the page on focus.
Don'tFlip hierarchy with weightA group heading must be clearly bigger or bolder than its options (meal detail: 16/600 group titles over 14/600 options). Before migration, the meal-detail modifier titles (14/600) matched the variant names (14/600) and were lighter than the add-on names (14/700).
Don'tGo below 11pxThe smallest text is t-overline at 11px. Counter badges (e.g. .filter-badge, 9px before migration) use 11px semibold.

TokenValueRule
  • Option rows: see Option card below for the card's inner spacing.
  • No margins on rows. Space comes from the parent: side padding from the body, gap between rows, and the heading's bottom margin above the first row.
  • One gap per boundary. If two containers meet, split the gap so the visible space still adds up to the token. For example, standalone Allergens uses 16px below plus the body's 24px on top, giving 40px.
  • No description? The first section still starts 24px under the title.

TokenValueUse
  • Never set a fixed height. Use min-height, so cards with a price line, photo or two-line name grow while keeping 16px on every side.
  • Controls (radio, checkbox, the add-on "Add" button) sit on the right, 16px in, centred vertically.
  • Cards stack --space-row (12px) apart. The first card sits --space-heading (12px) under its heading.

Using it in prototype.html

2 steps
  1. Add <link rel="stylesheet" href="design-system.css"> in <head>, after the is-desktop script.
  2. For new screens, use the classes (class="t-title-1") or the variables inside your own selectors:
/* New screen: Rewards */
.rewards-title   { font-size:var(--fs-title-1);  line-height:var(--lh-title-1);  font-weight:var(--fw-title-1); }
.rewards-section { font-size:var(--fs-title-3);  line-height:var(--lh-title-3);  font-weight:var(--fw-title-3); }
.reward-name     { font-size:var(--fs-headline); line-height:var(--lh-headline); font-weight:var(--fw-headline); }
.reward-desc     { font-size:var(--fs-body);     line-height:var(--lh-body);     font-weight:var(--fw-regular); }
.reward-expiry   { font-size:var(--fs-footnote); line-height:var(--lh-footnote); font-weight:var(--fw-regular); }

/* …or in markup */
<h2 class="t-title-1">Your rewards</h2>
<p class="t-body">Earn 1 point for every $1 spent.</p>
